# 笔记本部署验收记录

验收日期：2026 年 11 月 10 日。

## 部署结果

- 平台：Windows，JDK 21。
- 数据库：本机 SQL Server 2022 默认实例 `MSSQLSERVER`，已启动，启动类型为手动。
- 数据库名称：`course_selection`，已创建八张基础表。
- 部署模式：前后端合并为单个 JAR，由后台 Java 进程运行。
- 访问地址：`http://127.0.0.1:8081`，仅允许本机访问。
- 应用数据库身份：专用 SQL 登录，授予本项目数据库的读写角色。
- 初始数据：3 个账号、1 份学生档案、1 份教师档案、3 门课程与 3 个教学班。

## 已完成验证

1. 前端生产构建成功。
2. 后端 H2 环境的 19 项框架与业务测试全部通过。
3. 独立 SQL Server 验证库中的 11 项业务与并发测试全部通过；部署环境的 34 项只读 HTTP 检查全部通过。
4. 应用停止、后台启动正常；重启后账号数量、账号编号和密码散列未改变。
5. 关闭首次样例初始化后，三类角色仍可从 SQL Server 登录并查询数据。
6. SQL Server 原生数据库备份成功，`RESTORE VERIFYONLY ... WITH CHECKSUM` 检查通过。
7. 浏览器实际登录成功；工作台显示 Microsoft SQL Server，课程目录中文正常，直接刷新页面后仍可查询课程并恢复身份。
8. 本轮浏览器在独立验证库中完成档案新增、课程编辑、排课发布、学生选课、个人课表、教师名单和退课历史流程。
9. 更新前已生成数据库备份并保留旧 JAR；更新后八张业务表的记录数与校验值一致，详情见 release/windows/logs/upgrade-verification.json。

最近一次实际接口检查的逐项结果保存在 `release/windows/logs/verification.json`。备份使用 SQL Server 默认备份目录，可通过 `release/windows/backup.cmd` 再次生成备份。

## 已知边界

- 当前已部署档案、课程、学期、排课发布、选退课、课表、名单和账号安全；成绩与导入导出为后续扩展。
- 这是本机部署，尚未配置公网域名或 HTTPS。
- 已验证争抢最后名额与同一学生并发冲突；尚未进行大规模吞吐压测或数据库备份的实际恢复演练。
- Windows 集成认证在 JDBC 下出现域信任错误，因此应用改为使用独立 SQL 登录；建库与备份仍通过当前 Windows 账号执行。
