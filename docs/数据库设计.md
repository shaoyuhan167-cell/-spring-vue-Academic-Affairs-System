# 数据库设计

当前共八张表，与初次部署的表结构一致，业务开发未清空或重建部署库。

| 表名 | 用途 | 关键约束 |
|---|---|---|
| sys_user | 账号、姓名、角色、密码散列、状态 | username 唯一，角色为三类 |
| student | 学生学籍 | 学号唯一，账号唯一关联 |
| teacher | 教师档案 | 工号唯一，账号唯一关联 |
| course | 基础课程 | 编号唯一，学分、学时为正 |
| semester | 学期、选课窗口、学分上限 | 名称唯一，时间区间合法 |
| teaching_class | 具体教学班 | 关联课程、教师、学期，编号唯一 |
| course_schedule | 星期、节次、周次、教室 | 关联教学班，区间合法 |
| enrollment | 学生选退课记录 | 学生与教学班组合唯一 |

SQL Server 使用 backend/src/main/resources/db/schema-sqlserver.sql：IDENTITY 自增、BIT 布尔值、DATETIME2 日期时间、NVARCHAR 中文。H2 集成测试使用 backend/src/test/resources/db/schema-h2.sql。

## 已实现的保护

- 选退课依次锁定学期、学生与教学班，成功后才提交。
- 名额从 ENROLLED 记录实时统计，退课释放名额，不保存冗余人数。
- 同学期同课程不同班不可重复选择，唯一键进一步保护同班重复记录。
- 课表冲突比较星期、周次区间和节次区间。
- 发布教学班时检查教师与教室冲突。
- 退课改为 DROPPED 并记录 dropped_at；重选更新原记录并清空退课时间。
- 学分上限不能低于已有学生实际学分。
- 被开课引用的课程不可删除或修改编号、学分、学时。
- 有教学班的学期不可删除。
- 有选退课历史的教学班不可删除或改课程、教师、学期与排课；可调整容量或关闭。
- 人员通过停用账号保留历史，学号和工号不可变。

## 当前边界

排课采用连续周次和连续节次，尚未支持单双周、节假日调课和先修规则；成绩管理已通过新增模块实现。两类并发测试验证一致性，不代表已达到高并发吞吐目标。
